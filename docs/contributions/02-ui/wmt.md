### 2. 设计规范
* **配色方案**：以信息清晰易读为核心，制定了适合管理后台的沉稳主色调，并规范了用于状态提示的辅助色（如审核通过的绿色、驳回/警告的红色）。
* **字体与排版**：建立清晰的字体层级与字号梯度，确保数据看板中的数字和长表格信息在视觉上的易读性。
* **组件库搭建**：重点抽取并封装了管理端高频使用的通用组件，包括复杂数据表格、侧边导航栏、多功能数据卡片、分页器和操作确认弹窗等。
* **平台规范遵循**：严格遵循 Material Design 3 官方规范，注重后台操作的高效性、严谨性与专业感。

## 遇到的问题和解决
* **问题**：Figma AI 生成的初始原型较为基础，缺乏针对“内容审核”和“数据管理”等复杂后台业务逻辑的深度交互，且对于批量操作、状态流转的反馈不够完整。
* **解决**：我重新梳理了管理端的核心业务流（如：帖子从待审核到已通过/已驳回的状态流转，用户账号的封禁与解封逻辑）。随后在 Figma 中手动补全了数据表格的筛选交互、多状态切换效果，并特意增加了敏感操作（如删除、封禁）的二次安全确认弹窗与全局操作提示，确保了管理端操作流程的安全与闭环。

## 心得体会
本次 UI/UX 原型设计作业，让我深入体验了 B 端（后台管理系统）产品从业务梳理到界面落地的全过程。

首先，我深刻认识到管理端设计的核心在于“高效”与“清晰”。与前台页面不同，所有的设计都需要围绕帮助管理员快速处理数据和审核内容展开，这极大地锻炼了我的信息架构与逻辑排版能力。其次，在使用 Figma AI 工具辅助设计的过程中，我摸索出了“AI 生成基础框架 + 人工精调复杂业务逻辑”的高效工作流，学会了如何用精准的提示词引导 AI。最后，通过搭建高复用性的后台组件库，我建立了系统化的设计思维，也对 Web 端后台管理系统的交互逻辑有了更深刻的理解，为后续的产品开发打下了扎实的基础。
