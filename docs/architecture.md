# 校园学生积分互助网站 - 架构设计文档

## 1. 系统架构图

本项目采用前后端分离的架构设计，利用 Nginx 作为反向代理服务器分发静态资源和 API 请求，后端微服务化（单体模块化）处理业务逻辑，利用 MySQL 保障积分交易的强一致性数据存储。

## 2.前端架构与模块划分

用户与权限视图模块：负责学生学号实名制注册、教师工号专属登录的界面渲染与交互；处理 JWT Token 的本地存储、携带及状态校验；根据角色权限动态控制页面元素展示，并拦截越权的路由访问。

任务委托交互模块：承载互助需求完整生命周期的前端交互流程，实现标准化表单的渲染、校验与提交；可视化呈现需求状态机流转（待审核 -> 待接单 -> 进行中 -> 已完成 / 已取消），并同步状态变更后的页面展示。

积分事务可视化模块：系统核心的积分交互前端模块。负责积分悬赏发布时预扣除锁定状态的可视化展示、接单完成后积分划转结果的实时反馈，以及取消委托时按比例违约扣除规则的前端呈现与金额计算；同步后端事务结果，保障积分展示的一致性。

内容与系统运营视图模块：负责管理端数据可视化看板的渲染（统计展示系统活跃量、累计量等核心指标）；处理合规审核操作的前端交互（同意 / 驳回操作触发及审核结果同步通知展示）；实现管理端手动执行用户封禁、积分调整的操作界面与结果反馈。

## 3. 后端服务与模块划分
根据系统需求，后端架构划分为以下几个核心模块：

用户与权限模块：负责学生学号实名制注册、教师工号专属登录的身份识别；维护 JWT Token 签发与验证；根据角色拦截越权访问。

任务委托模块：管理互助需求的完整生命周期，处理标准化表单提交；维护需求状态机流转（待审核 -> 待接单 -> 进行中 -> 已完成 / 已取消）。

积分事务管理模块：系统最核心的资产模块。负责积分悬赏发布时的预扣除锁定、接单完成后的安全划转，以及取消委托时的按比例违约扣除。该模块必须依赖数据库事务(Transaction)保证强一致性。

内容与系统运营模块：负责对接管理端的数据可视化看板（统计系统活跃与累计量）；处理合规审核（同意/驳回及同步通知）；管理端手动执行的用户封禁与积分调整操作。
